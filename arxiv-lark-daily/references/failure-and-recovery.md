# 失败与恢复

## 写入前停止

以下情况不得继续写入：

- 缺少 `lark-cli` 或 user 登录无效；
- 目标 Base 同名不唯一；
- 已有表结构不符合固定字段契约且表内已有记录；
- 空表 schema 修订失败或修订后验收失败；
- 配置中的检索字段、关键词、匹配方式、分类格式或 `retention_days` 无效；
- arXiv 响应损坏、分页索引不一致或结果窗口过大；
- 待写论文缺少中文摘要；
- 待写论文标签不是 2–4 个、最长 6 个字、含中文且不重复的合法技术标签；
- 标签选项更新后读回确认失败；
- 记录创建响应无法确认唯一 `record_id`。

## 网络重试

连接失败、超时、HTTP 429、500、502、503、504 可以按上限重试。遵守 `Retry-After`，且 arXiv API 重试间隔不得少于 3 秒。非法查询和其他 4xx 错误不自动重试。

## 单篇论文失败

摘要翻译或标签生成失败时不得写入该论文。标签选项更新失败时不得创建任何依赖缺失标签的新记录。

## 写入恢复

每次成功创建记录后立即保存 `record_id`。恢复时：

1. 重新读取表中已有链接；
2. 将原始 URL 和 Markdown 链接都规范化为 abs URL；
3. 已存在的 abs URL 不再创建；
4. manifest 中有记录 ID 时复用，但仍要再次执行 URL 去重。

收到不确定的创建响应时，不要盲目重试创建；先按 abs URL 查询。

## 本地状态清理

配置项 `retention_days` 默认 30。新批次确定后，以最新 `submitted_date` 为基准清理本地 manifest 中早于“最新 `submitted_date` 往前 `retention_days` 天”的论文条目；保留窗口两端均为闭区间。清理可能在 fetch 阶段和 write 阶段各执行一次，操作幂等，只清理本地恢复状态，不删除飞书表格中的历史记录。

## 输出脱敏

不得输出 token、device code、App Secret 或完整认证响应。可以输出 Base 和数据表名称、公开 arXiv 链接、论文 ID 和本地运行产物路径。
